# Патчинг SWF на лету (ветка `swf-patch`)

Эксперимент по производительности: прокси клиента патчит SWF-файлы игры
прямо в полёте, снимая фильтры (GlowFilter, DropShadowFilter, …) и
`cacheAsBitmap`.

## Зачем

Любой фильтр на клипе — и во Flash, и в Ruffle — принудительно включает
offscreen-кэширование поддерева в текстуру. Когда клип анимируется, кэш
перерисовывается каждый кадр, а при изменении пиксельных границ текстура
ещё и **пересоздаётся**. Профиль живой сессии показал ~13 000 аллокаций
текстур за 5 минут (размеры 30–65×110–119 px — элементы персонажей), все
от фильтрованных клипов. Явный `cacheAsBitmap=true` в контенте игры не
используется вовсе: всё кэширование наведено фильтрами.

Замер по реальным файлам: `base.swf` — 21 список фильтров + 6 динамических
обращений из AS2; аватарный риг `4pydl5s0lc.swf` (грузится по разу на
персонажа) — 82 списка.

## Что делает патч (`src-tauri/src/swf_patch.rs`)

1. `PlaceObject3`: вырезает список фильтров, снимает флаг `HAS_FILTER_LIST`.
2. `PlaceObject3`: обнуляет байт `cacheAsBitmap` (парсится как явное «не
   кэшировать»).
3. AVM1-байткод: переименовывает строки-свойства `filters` → `f1lters` и
   `cacheAsBitmap` → `cacheAsB1tmap` (только точные NUL-терминированные
   вхождения, длина не меняется — все смещения в байткоде остаются
   валидными). Динамическое `clip.filters = [glow]` превращается в
   безвредную запись обычного свойства.

Патч применяется в `official_proxy` (все `*.swf` через прокси) и при
кэшировании `base.swf`. Ответ помечается заголовком
`x-shararam-swf-patched: filters-stripped`, в профиль пишется событие
`patch/swf` со статистикой по каждому файлу.

Всё fail-open: не-SWF, LZMA, битый тег или нулевые изменения — отдаются
исходные байты; неразобравшийся тег копируется как есть (`skipped_tags`).

## Цена

Визуально пропадают свечения/тени на фильтрованных клипах — это и есть
предмет A/B-сравнения. На каждый SWF при загрузке тратится
распаковка+запаковка zlib (десятки мс для больших файлов, единицы для
мелких).

## Выключить

`SHARARAM_SWF_PATCH=0` — прокси отдаёт оригинальные байты (сравнительный
прогон без пересборки).

## Проверка

- `cargo test swf_patch` — юнит-тесты на синтетическом SWF.
- `SWF_PATCH_REAL_DIR=<папка> cargo test real_files -- --ignored --nocapture`
  — прогон по реальным скачанным файлам (+`SWF_PATCH_DUMP_DIR` чтобы
  сохранить результат).
- Пропатченные `base.swf` и риг проверены парсером `swf` из нашего форка
  Ruffle: столько же тегов/спрайтов, 0 фильтров, полный строгий парс OK.
